# CampusOps — Intelligent Campus Operations Platform

CampusOps is a campus operations platform concept that brings building exploration, classroom information, maintenance requests, room bookings, staff coordination, inventory, incidents, and analytics into one interface.

Its visual experience is designed around an interactive 3D campus building. Users can select a floor to open a top-down floor plan, select a classroom to inspect its capacity and status, and use a website-aware AI assistant to find campus information or prepare operational requests.

## Features

### 3D campus explorer
- Interactive 3D building visualization.
- Floor selection and navigation.
- Hover and selection feedback.
- Building overview and operational indicators.

### Top-view floor plans
- Classroom outlines and room labels.
- Room number, capacity, type, and availability.
- Room details, facilities, equipment, and maintenance information.
- Filters for capacity, room type, availability, and facilities.
- Floor-plan zoom, pan, and reset controls, where implemented.

### Campus operations
- Maintenance complaint intake.
- Incident grouping and duplicate detection.
- Room booking and conflict detection.
- Technician skills, shifts, availability, and work assignments.
- Inventory and spare-part reservations.
- Purchase and repair approvals.
- SLA tracking, escalation, notifications, and analytics.

### AI assistant
The assistant is intended to answer questions using campus information the signed-in user is authorized to access. Depending on the implemented backend, it may help users find rooms, check availability, summarize incidents, locate inventory shortages, or prepare maintenance and booking requests.

The AI must not independently bypass permissions or make final decisions about stock, bookings, approvals, or state transitions. Those rules belong in deterministic backend logic.


For a Vite-based app, the production output is commonly written to `dist/`. Follow the actual build configuration in your project.

## AI assistant and API key security

For live AI functionality, the frontend should send a request to your backend, and the backend should call the AI provider.

Recommended request flow:

1. A user submits a question in the CampusOps assistant.
2. The frontend sends the message and relevant page context to an authenticated backend endpoint.
3. The backend checks the user's identity and permissions.
4. The backend retrieves only the campus records the user is authorized to see.
5. The backend calls the configured AI provider and, when appropriate, invokes a limited set of validated backend tools.
6. The backend validates any proposed action and asks the user for confirmation or approval when required.
7. The frontend displays the response and any resulting record links.

### Key handling checklist

- Store `OPENAI_API_KEY` on the server in an environment variable or secrets manager.
- Never embed a private key in JavaScript, HTML, browser storage, or a frontend `.env` variable.
- Never return the complete saved key in an API response. Display a masked value if needed.
- Restrict who can configure or replace AI credentials.
- Validate requests, set reasonable usage limits, and handle provider errors.
- Do not allow the AI to run arbitrary SQL or bypass authorization.
- Do not log API keys or sensitive user data.
- If users supply their own key, explain how it is stored and who can use it.

Example backend environment variables:

```dotenv
OPENAI_API_KEY=replace_with_your_key
OPENAI_MODEL=replace_with_a_supported_model
```

Use the model name supported by your provider account and backend implementation. Do not add a real key to this README.

## Suggested campus workflows

### Scenario 1: A classroom is unavailable before an exam

1. A faculty member reports a fault in a booked room.
2. The system identifies the building, floor, room, and urgency.
3. The backend marks the room unavailable after validating the request.
4. The system identifies affected bookings and suggests suitable alternatives.
5. An eligible technician is assigned.
6. Required spare parts are reserved, or the work order is marked blocked if stock is unavailable.
7. Relevant users receive notifications, and all important changes are recorded.

### Scenario 2: Multiple users report a Wi-Fi outage

1. Similar complaints arrive from multiple users.
2. The system identifies likely duplicates and links them to a shared incident while retaining individual reports.
3. The incident summary lists affected buildings and relevant details.
4. A qualified technician is assigned based on skills, shift, availability, and workload.
5. If the technician becomes unavailable, the system rechecks eligibility and reassigns the work.
6. Notifications, SLA tracking, and dashboard metrics are updated.

These scenarios require backend logic and persisted data; a frontend-only prototype can demonstrate the interface but cannot guarantee the operational rules.

## Security requirements

Before using CampusOps with real users:

- Enforce role-based access on the backend for every protected operation.
- Do not trust roles or permissions supplied by the browser.
- Use database transactions and appropriate constraints for booking and inventory operations.
- Prevent overlapping confirmed bookings.
- Prevent negative available inventory and duplicate stock deductions.
- Enforce approval rules and separation of duties.
- Revalidate relevant constraints immediately before executing approved actions.
- Make event processing idempotent so repeated webhooks do not repeat operational actions.
- Validate all inputs and use parameterized database access.
- Keep an audit trail for important actions.
- Configure CORS for trusted frontend origins.
- Use HTTPS and appropriate secret management in production.

## Troubleshooting

### `npm` is not recognized

Install Node.js, close and reopen the terminal, then check:

```powershell
node --version
npm --version
```

### `npm run dev` fails

- Confirm that the terminal is in the directory containing `package.json`.
- Run `npm install`.
- Read the exact error and check the scripts in `package.json`.
- Confirm that your installed Node.js version is compatible with the dependencies.

### The page loads but data is missing

The frontend may still be using demo data, or the backend/database may not be configured. Check the browser console, backend logs, API base URL, and database connection.

### AI assistant reports a missing key

Configure the key in the backend's environment or secrets manager using the variable name expected by the code. Restart the backend after changing environment variables. Do not paste private keys into chat or commit them to the repository.

### API requests fail

Confirm that the backend is running, the frontend points to the correct API URL, CORS is configured for the development origin, and authentication headers are handled correctly.
